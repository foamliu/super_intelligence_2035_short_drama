# 超级智能2035 · 短剧制作

将《超级智能2035》（42章）改编为AI生成短剧集。每集约6-12分钟，单集独立成篇，串联成完整叙事。

**核心主题**：在AI逐步接管判断、协作与分配的世界里，人如何变化。

### 版本控制

使用 Git 进行全项目版本管理：

| 管理对象 | 策略 | 说明 |
|----------|------|------|
| 分镜脚本（.md） | 全量追踪 | 文本文件，diff 友好，每次修改后提交 |
| 工作流（.json） | 全量追踪 | ComfyUI 工作流，格式稳定利于版本对比 |
| 素材清单（manifest.json） | 全量追踪 | 每章素材元数据 |
| 角色参考图（.png） | 全量追踪 | 定妆照确认后锁定，变更需标注原因 |
| 生成素材（ASSETS/{章节}/） | .gitignore 排除 | 生成物体积大，通过 manifest.json 间接管理 |
| 成片（OUTPUT/） | .gitignore 排除 | 成品文件，不入库 |

**分支策略**：`main` 分支保持可发布状态；每章制作使用 `ep/{章节号}` 特性分支，完成验收后合并。

## 四、统一视觉风格

### 总体原则

- **现实质感**：不追求过度科幻感，保持日常光影与细节
- **人物审美**：俊男美女，符合短剧市场主流审美，但保持自然感（非网红脸/过度磨皮）
- **低饱和度**：整体偏灰、偏冷（历史章节除外）
- **固定画幅**：统一16:9

### 人物审美标准

| 维度 | 标准 |
|------|------|
| 颜值 | 俊男美女，符合主流短剧审美 |
| 妆造 | 自然裸妆，不夸张，贴合角色身份 |
| 质感 | 保留皮肤纹理，不追求过度磨皮 |
| 气质 | 贴合角色设定（研究员有书卷气，工人有劳动感，老人有岁月痕迹）|

### 审美优先级建议

"短剧市场审美"与"自然质感/保留纹理"存在天然张力。建议按场景类型分档处理：

| 优先级 | 场景类型 | 处理策略 |
|--------|----------|----------|
| **质感优先** | 老工人（王建国）、老人（赵淑芬）、出租车司机（老周）、非洲诊所（奥蒂诺） | 保留皮肤纹理、皱纹、汗渍，强调真实劳动感——这本身就是这类角色的视觉说服力 |
| **平衡** | 主角中景对话（林薇、陈思危、墨子界面） | 自然光感 + 适度美化，不过度磨皮但确保"上镜感" |
| **审美优先** | 直播间出镜（林薇、周沫）、历史美人（陈圆）、跨文化精英（莉娜·陈） | 可适度提升面部平整度和光影柔和度，因为这符合角色所处场景的视觉逻辑（直播自带滤镜、宋代审美理想化、精英形象管理） |

> **核心原则**：不搞全局统一磨皮。让审美策略**服务于场景说服力**，而非反过来。

## 五、角色一致性技术路线

跨镜头、跨章节的角色面部一致性是AI生成短剧的核心难点。以下技术路线用于锁定同一角色在不同画面中的外观。

> ⚠️ **人像一致性风险评级：中等（无商用级确定性方案）**
> 
> 当前方案（IPAdapter + FaceID + 关键词锁定）是开源工具链中性价比较高的路线，但**无法保证同一角色跨镜头的面庞精确一致**。这意味着：
> - 每镜需生成 4-6 张候选、人工筛选，后期筛片成本占 T2I 总工时 20%-40%
> - 同一角色在不同镜头间可能出现"像但不确定是不是同一个人"的偏差
> - 长剧集中人物一致性的工程瓶颈是当前 AI 视觉制作的核心未解决问题
> 
> **协作预期**：协作者需建立"80 分一致性"的合理预期——目标是在给定场景/光影条件下保持风格和大致面貌的统一，而非像素级的身份锁定。商业级方案（专有模型 + 角色 LoRA 精调 + 多轮人工修图）不在本项目开源工具链范围内。

### 定妆流程

1. **初稿生成**：对角色首次出现的镜头，T2I 批量生成 6-8 张候选（正面、半侧面、不同表情）
2. **筛选定稿**：人工选出最佳定妆照，确保五官清晰、气质贴合角色设定
3. **入库**：所有角色定妆参考图统一存入 `ASSETS/CHARACTERS/{角色名}/`，不分常驻/章节角色

### 一致性控制工具

| 工具 | 用途 | 适用场景 |
|------|------|----------|
| IP-Adapter + FaceID | 用定妆参考图锁定面部特征 | 所有含角色的 T2I 生成 |
| 角色 LoRA | 针对高频角色训练轻量 LoRA | 常驻主角（贯穿多章的角色）|
| 定妆参考图直输 | I2V 阶段以定妆照作为起始帧 | 关键对话镜头、特写 |

### 跨章节一致性策略

- 所有角色定妆参考图统一存放于 `ASSETS/CHARACTERS/{角色名}/`
- 每章开拍前，从 `ASSETS/CHARACTERS/` 拉取所需角色定妆照，作为该章 T2I 的 IP-Adapter 输入
- 若某章角色外观需随剧情变化（年龄、着装），在对应角色目录下追加变体参考图（如 `林薇/林薇_2035春.png`），并在分镜脚本中标注

## 六、BOOK 与 SCENES 的关系

- **BOOK/** — 原著 42 章完整书稿（Markdown），是 SCENES 的唯一叙事源。所有人物设定、对话、旁白、时间线均以 BOOK 为准。
- **SCENES/** — 分镜脚本，是 BOOK 的**视觉改编产物**，非原文复制。截至当前覆盖 25 章，其中详细脚本 14 章、框架占位 11 章。

### 覆盖策略

| 梯队 | 数量 | 策略 |
|------|------|------|
| 第一梯队（制作中） | 7 章 | 独立性强、视觉集中、单人/少场景（第 2/8/12/18/19/21/33 章） |
| 第二梯队（已框架） | 13 章 | 推动主线或优质独立篇，场景+镜头结构完整待细化 |
| 第三梯队（已框架） | 5 章 | 补完填充，细节待补充 |
| 待评估 | 17 章 | 可能通过旁白/蒙太奇串联，不一整章改编 |

### BOOK ↔ SCENES 同步机制

1. **修改 BOOK**（人物设定、对话、时间线）→ 同步更新 `BOOK/profiles.md`、`BOOK/timeline_analysis_revised.md`、`BOOK/glossary.md`
2. **涉及 SCENES 的分镜变更** → 在对应 `.md` 中标注变更原因和日期
3. **新角色出场** → 在 `BOOK/profiles.md` 追加人物小传 → 关联的 SCENES 脚本引用 profiles 中的角色标签
4. **连续性核验** → 每集成片后对照 `BOOK/timeline_analysis_revised.md` 做交叉验证（详见第十四节"叙事连续性审核"）

> SCENES 中"框架占位"的章节包含场景划分和关键镜头提示，可据此直接生成初版素材。待立项后由分镜师细化为逐镜脚本。

## 七、分镜脚本规范

### 文件结构

分镜脚本采用**单文件**格式，将角色设定、场景列表、逐镜描述合并在一个 `.md` 文件中。当前范例：`SCENES/12_身体.md`。

```
SCENES/
└── 12_身体.md    # 单文件分镜脚本（含角色设定、场景列表、逐镜详情）
```

> 单集脚本超过 500 行时可拆分为 `BEAT_SHEET.md` + `SHOT_LIST.md`，当前量级单文件完全够用。

### 分镜脚本内容要素

每个脚本至少包含以下部分（参见 `SCENES/12_身体.md`）：

1. **片头信息**：改编来源、片长预估、核心主题、视觉风格
2. **角色设定**：出场角色、年龄、身份、核心特征、声音/动作特征
3. **场景列表**：地点、时间、核心事件
4. **逐镜详情**：镜号、景别、画面内容、台词/旁白、情绪、生成方式

### 景别标准

| 景别 | 画面范围 | 用途 |
|------|----------|------|
| 特写 | 人脸/手部/局部 | 情绪细节 |
| 近景 | 肩部以上 | 对话、表情 |
| 中景 | 膝部以上 | 两人互动 |
| 全景 | 全身 | 环境交代 |
| 远景 | 大场景 | 氛围建立 |

### 关键帧标记

| 标记 | 含义 |
|------|------|
| ★ | 关键帧，需高质量生成 |
| ◆ | 含AI界面/屏幕，需后期合成 |
| ▲ | 需动态生成（I2V） |

### 云端替代方案

> 无 24GB+ 本地 GPU 的协作者，可通过以下云端方案参与：

| 平台 | 最低配置 | 优势 | 劣势 |
|------|----------|------|------|
| **RunPod** | RTX 4090 / 24GB | 按小时计费，预装 ComfyUI 模板 | 需自行上传工作流和模型 |
| **ThinkDiffusion** | RTX 4090 | ComfyUI 原生支持，一键启动 | 按时长订阅，不适合零散使用 |
| **ComfyUI Online** | T4 / 16GB | 免费额度可用 | 显存 16GB，部分工作流需降配运行 |

> 推荐首次试跑使用 RunPod RTX 4090（约 $0.50-$0.80/小时），确认工作流通用后再批量到 Modal。

## 十、ComfyUI 工作流清单

所有工作流以 `.json` 格式存放于 `workflows/` 目录。

### 图像生成与处理

| 工作流文件 | 用途 | 输入 | 输出 |
|-----------|------|------|------|
| `Z-Image-Turbo 文生图.json` | 文生图（主） | Prompt | 1280×720（16:9）|
| `Flux.1 Dev 文生图.json` | 文生图（备/高质量）| Prompt | 1280×720（16:9）|
| `Image Edit (LongCat Image Edit).json` | 图像编辑/修复 | 图+指令 | 编辑后图像 |
| `Image Segmentation (SAM3).json` | 图像分割/抠图 | 图 | 蒙版/Mask |
| `Image to Pose Map (SDPose Multi-Person).json` | 多人姿态提取 | 图 | 姿态骨架图 |
| `Pose to Image (Z-Image-Turbo).json` | 姿态→图像 | 姿态图+Prompt | 指定姿态的人物图 |
| `Image to Model (Hunyuan3d 2.1).json` | 图像→3D模型 | 图 | 3D模型文件 |

### 视频生成

| 工作流文件 | 用途 | 输入 | 输出 |

### 配乐策略

按场景情绪预置 Prompt 模板，确保风格统一：

| 情绪类型 | 适用场景 | Prompt 方向 |
|----------|----------|-------------|
| 沉思/内省 | 林薇独白、实验室深夜、回忆段落 | 极简钢琴或弦乐，缓慢节奏，留白多 |
| 紧张/冲突 | 决策转折、数据异常、伦理辩论 | 低音脉冲、电子纹理、渐进式节奏 |
| 温暖/人性 | 赵淑芬（12）、老周（18）、历史章节（19/21） | 民乐元素或木吉他，自然残响，暖色调 |
| 城市/日常 | 上海街景、深圳实验室日常 | 环境音为主（车流、键盘、空调底噪），音乐退居次位 |
| 空灵/未知 | 墨子界面、ASI 意识流、远景空镜 | 合成器 Pad，泛音丰富，无明确旋律线 |

### 音效库方案

| 层级 | 来源 | 说明 |
|------|------|------|
| **合成音效** | ACE-Step 1.5 文生视频.json | UI 交互音（墨子粒子特效声）、数据流、科幻提示音等无现实参照的音效 |

| **环境底噪** | 实景录制或素材库 | 实验室空调、班加罗尔街头、网约车行驶——每场景独立采集，保持空间连续性 |

### 混音流程

```
┌──────────────────────────────────────────────────┐
│ 1. 对白/旁白（Qwen3-TTS）→ 主干音轨             │
│    - 统一归一化到 -23 LUFS（响度标准）            │
│    - 降噪、去齿音处理                             │
├──────────────────────────────────────────────────┤
│ 2. 环境底噪 → 连续铺底                           │
│    - 每场景独立铺设，跨镜头连续不中断             │
│    - 音量拉至 -28 ~ -32 LUFS，不抢主干           │
├──────────────────────────────────────────────────┤
│ 3. 配乐（ACE-Step 1.5）→ 情绪引导轨             │
│    - 仅在需要情绪提升的段落加入                   │
│    - 淡入淡出 ≥ 1 秒，避免突兀切入               │
│    - 音量控制在 -25 ~ -30 LUFS                    │
├──────────────────────────────────────────────────┤
│ 4. 重点音效 → 定点放置                           │
│    - UI 交互音、关键动作音按帧精准对齐            │
│    - 峰值不超过 -12 dBFS                          │
├──────────────────────────────────────────────────┤
│ 5. 母带 → 响度标准化 + 动态控制                  │
│    - 整体输出 -23 LUFS（YouTube/Vimeo 标准）      │
│    - 峰值限制器 -1.0 dBTP                         │
└──────────────────────────────────────────────────┘
```

### 字幕生成策略

| 环节 | 工具/方式 | 说明 |
|------|-----------|------|
| **旁白/台词文本** | 分镜脚本直接导出 | 脚本中的台词/旁白即为字幕源文本，无需额外转录 |
| **时间轴对齐** | DaVinci Resolve 自动对齐音频 | 导入语音音频后利用 Resolve 语音识别功能自动打时间轴 |
| **字幕格式** | SRT（标准外挂字幕） | 编码 UTF-8，与成片封装一同交付，也支持软字幕开关 |
| **双语字幕** | 分镜脚本提供英译 | 每集脚本预留英文台词栏位（可选），满足国际发行需求 |
| **风格统一** | ASS 样式模板 | 白字黑边/半透明底，字体思源黑体 Medium，字号匹配 1080p |

> 字幕 QC：每集成片导出后，以 1.5 倍速通读字幕文件，检查时间轴偏移（阈值 ≤ 0.3 秒）、错别字、标点残漏。

## 十四、质量验收标准

每个章节成品在进入后期剪辑前，需通过以下质量门禁：

| 检查项 | 通过标准 | 不通过处理 |
|--------|----------|------------|
| 画面清晰度 | 无明显 AI 伪影（多余手指、五官变形、纹理粘连） | 重新生成该镜 |
| 角色一致性 | 同一角色在同场景内面部特征差异可接受（不出现"换人"感） | 调高 IP-Adapter 权重重新生成 |
| 光影连贯 | 同场景内光照方向和色温基本一致 | 调整 Prompt 或后期调色 |
| 运动质量 | I2V 无明显画面撕裂、闪烁、物体突变 | 降速重生成或换 Wan 2.2 |
| 台词同步 | 旁白/台词与对应画面时码偏差 < 0.3 秒 | 微调剪辑或重新生成音频 |
| 叙事连续性 | 同一角色跨集经历不矛盾、跨集提及的事件前后一致 | 修编相关章节脚本或追加过渡镜头 |
