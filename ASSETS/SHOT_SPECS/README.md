## Prompt 格式约定

每张图的 prompt 遵循项目统一格式：

```yaml
画面: <完整中文画面描述，含角色/环境/光线/表情/构图>
尺寸: <1920x1920 | 1920x2560 | 2560x1920>
Seed: <固定整数以实现可重复生成>
负面词: <逗号分隔英文>
文件: <输出文件名.png>
```

负面词使用英文（豆包 API 规范），画面描述使用中文（更好的语义匹配）。

## 工作流集成建议

1. **定妆图（P0）** → 豆包 T2I 直接生成 → 存入 `ASSETS/CHARACTERS/{角色名}/`
2. **场景图（P1+P2）** → 豆包 T2I 生成 base → 存入 `ASSETS/BACKGROUNDS/`
3. **变体镜头** → 用 P0/P1 生成的图作 base，在 ComfyUI 中用 IP-Adapter + ControlNet 重绘
4. **UI 镜头** → 单独设计 UI 素材 → 与场景图合成
5. **动态镜头** → 用生成的图作首帧，通过 LTX-2.3 / Wan 2.2 图生视频

## T2I Prompt 版本管理策略

> AI 生成的画面在不同模型/参数下差异显著。版本号记录了"这张图是用什么条件跑出来的"，是唯一可追溯的锚点。

### 版本号规范

```
{集编号}_{角色/场景}_{序号}_v{版本号}.png

示例：
18_laozhou_01_frontal_v1.png    # 第18集，老周定妆照1，第1版
18_laozhou_01_frontal_v2.png    # 同一镜头，调参后重新生成
18_car_01_night_driving_v1.png  # 第18集，车内场景1，第1版
```

### 何时升级版本号

| 变更类型 | 是否升级版本 | 说明 |
|----------|:----------:|------|
| Prompt 文案微调（措辞/形容词） | ✅ | 任何语义变化都可能影响输出 |
| Seed 值变更 | ✅ | 不同 seed 产出不同画面 |
| 模型切换（如 Flux→Z-Image） | ✅ | 跨模型差异显著，必须标记 |
| IP-Adapter/ControlNet 权重调整 | ✅ | 直接影响人脸一致性或构图 |
| 分辨率/尺寸变更 | ✅ | 重新生成 |
| 仅重命名文件 | ❌ | 内容不变 |
| 后期修图（手动修瑕疵） | ❌ | 修图后追加 `_fixed` 后缀，不改版本号 |
| 超分 | ❌ | 超分后追加 `_upscaled` 后缀 |

### Prompt 版本记录

每集的 T2I Prompt 文件末尾维护一张 **Prompt Changelog**：

```markdown
## Prompt Changelog

| 日期 | 镜头 | 版本 | 变更说明 | 产出文件 |
|------|------|------|----------|----------|
| 2026-07-22 | 老周-01 正面定妆 | v1 | 初版，Flux.1 Dev，seed=42 | 18_laozhou_01_frontal_v1.png |
| 2026-07-23 | 老周-01 正面定妆 | v2 | IP-Adapter 权重 0.7→0.85，修复面部偏差 | 18_laozhou_01_frontal_v2.png |
| 2026-07-23 | 车内-01 驾驶位 | v1 | 初版，Z-Image-Turbo，seed=123 | 18_car_01_night_driving_v1.png |
```

> **原则**：每条变更说明足够让协作者理解"为什么重跑"，无需对照两张图才能判断。

### 版本回退

若 v2 效果不如 v1，直接在 Changelog 中标注 v2 废弃，后续沿用 v1：

```markdown
| 2026-07-23 | 老周-01 正面定妆 | v2 | ❌ 废弃——肤色偏冷与角色设定不符，回退至 v1 | — |
```

推荐按以下顺序组织画面描述，确保每次生成的 prompt 信息密度一致：

```
[环境/场景] + [角色位置与动作] + [表情/神态] + [光线方向与色温] + [构图景别] + [色调/氛围]
```

示例（第18集老周定妆照）：

> "深夜网约车驾驶位，老周45岁中国男性靠在座椅上，疲惫侧脸望向窗外，车窗外城市霓虹灯光透过雨滴投射在脸上，暗蓝色调冷光从仪表盘打在下半张脸，近景肩部以上构图，低饱和度偏蓝灰，电影感写实光影"
